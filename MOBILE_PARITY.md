# AquaWatch: перенос сценариев мобильного приложения

## Изученные источники

- `alishka07/aquawatch_-mobile`, `main`, commit `e5447be360b612ae51b60baf478aa05b922df21e`: интерактивный прототип `AquaWatch.dc.html` и сайт приложения.
- Ветка `claude/mobile-app-react-native-wtoqfs`, commit `8842587b9c359e631240e2da0dd32816e8b14b06`: React Native / Expo, 18 экранов, Zustand, AsyncStorage, native maps, экспорт.
- Локальный landing page SuBulaq используется как визуальный ориентир: светлая бумажная подложка, сдержанный зелёный, крупная типографика и изображения аппарата.

Обе мобильные реализации используют синтетические измерения и сценарии управления. В них нет подключённого MQTT-клиента, серверной авторизации, видеопотока с аппарата или работающей CV-модели. В прототипе подключается Google Maps; в native-ветке используется react-native-maps. Библиотеки проверки телеметрии в native-ветке не подключены к транспорту или экранам.

Веб-реализация использует общие данные флот/пробы/события. Изменение фильтра отчёта меняет график, статистику, журнал и выгрузку. При сравнении предыдущий период той же длительности совмещается по временной оси с выбранным; отсутствующий период обозначается пустым.

## Отличия от мобильного интерфейса

- Нет настоящей авторизации: в мобильном прототипе кнопка входа тоже только открывает интерфейс. В веб-версии используется локальное рабочее пространство.
- Интерфейс на русском. Мобильный переключатель RU/KZ/EN меняет сохранённый код языка, но не переводит экраны; полноценная локализация не заявляется.
- Сохранение в браузере не означает PWA или гарантированную работу без сети. Мобильный offline-переключатель также не реализует очередь синхронизации.
- Мобильный спутниковый слой и картографические данные Google/Apple не переносятся на схематичную веб-карту. Для настоящей географической карты требуется выбрать картографический сервис и настроить доступ.
- PDF формируется через системную печать браузера. Если новое окно заблокировано, скачивается HTML-отчёт. Нативный мобильный «Поделиться» заменён браузерной загрузкой; `.xls` не имитируется TSV-файлом.
- Скрининг микрочастиц и индексы качества — демонстрация. Отчёт не является лабораторным протоколом или подтверждением соответствия ГОСТ/ПДК.

## Контракт для будущей телеметрии

В native-ветке описана MQTT-тема `subulaq/<vessel>/telemetry`, предполагаемая частота 1 Гц и версия схемы `v: 1`:

```ts
type QualityFlag = "ok" | "stale" | "error";
type TelemetryMessage = {
  v: number;
  vessel: string;
  ts: string; // ISO 8601: время измерения на борту
  seq: number; // сквозной счётчик сообщений
  lat: number;
  lon: number;
  ph: number;
  turb_ntu: number;
  t_c: number;
  tds_ppm: number;
  q_ph: QualityFlag;
  q_turb: QualityFlag;
  q_t: QualityFlag;
  q_tds: QualityFlag;
};
```

Парсер reference-ветки проверяет диапазоны координат/датчиков, читаемое время, целый неотрицательный `seq`; отсутствующий флаг качества считает `error`. Есть функции обнаружения пропусков `seq` и полноты ряда. Для реального подключения потребуется транспорт, сохранение сообщений, контроль свежести/дубликатов/перезапуска счётчика и отображение недостоверных показаний. Текущая веб-версия такие сообщения не принимает.

В мобильном экспортном контракте дополнительно есть `seq`, `quality`, `threshold_ntu`, `threshold_source`, `operator`. Веб-CSV вместо выдуманной телеметрии явно пишет `data_source=demo_simulation` и `coordinate_source=demo_map_projection`. При подключении борта эти поля и реальные координаты нужно связать с валидированным сообщением.

## Проверка отчётов

```powershell
node --experimental-strip-types --test tests/report.test.mjs
```

Проверяются границы дат до последней миллисекунды дня, неверный период, сортировка и фильтр аппарата, пересчёт сводки, защита CSV от формул в именах и ID, экранирование HTML и состав колонок.
