# AquaWatch × SuBulaq

Рабочий веб-интерфейс мониторинга воды на основе AquaWatch, с функциями мобильного прототипа и визуальным стилем лендинга SuBulaq.

## Запуск

Нужен Node.js 24+ (проверено на 24.4) и npm.

```powershell
npm ci
npm run dev -- --host 127.0.0.1 --port 3000
```

Откройте http://127.0.0.1:3000. Приложение работает в деморежиме без API-ключей. Разделы доступны через адреса `/#overview`, `/#map`, `/#devices`, `/#missions`, `/#analytics`, `/#manual`, `/#journal`, `/#service`, `/#settings`, `/#profile`.

## Возможности

- Обзор флота и последних измерений: pH, мутность, температура, TDS, проводимость, микрочастицы.
- Схема водоёма с перемещением и масштабированием, фильтрами, точками измерений и редактором маршрутов. Готовый маршрут доступен с клавиатуры и на телефоне.
- Флот: поиск, фильтры, добавление аппарата с проверкой дубликата серийного номера, управление и история.
- Миссии: последовательное прохождение точек, пауза, продолжение, возврат на базу, аварийная остановка. Остановленный аппарат не подключается сам.
- FPV-симулятор: управление удержанием кнопки или стрелками, выбор камеры, снимок SVG, демонстрационная проба, проверка потери связи. Отпускание, потеря фокуса и глобальная пауза останавливают ручное движение.
- Аналитика: восемь показателей, фильтры дат и аппаратов, сравнение периодов, карточки проб, статистика, экспорт CSV и печать в PDF.
- Уведомления и журнал: фильтры, прочитанные события, экспорт JSON.
- Обслуживание: ресурс мембраны, отметка замены, записи калибровок по аппарату. Каждая добавленная демопроба расходует ресурс мембраны.
- Настраиваемые пороги с проверкой корректности и учебными профилями; профиль оператора.
- Флот, измерения, журнал, профиль, обслуживание и пороги сохраняются в localStorage. Черновик маршрута и нажатые кнопки ручного управления после перезагрузки не восстанавливаются.

## Источники и границы реализации

Основной проект: https://github.com/alishka07/AquaWatch

Функциональный референс: https://github.com/alishka07/aquawatch_-mobile (изучены HTML-прототип и ветка React Native).

Дизайн: предоставленный лендинг SuBulaq — палитра paper/sand/mist/sage/olive/forest, Onest, Oranienbaum, цветная вертикальная навигация и светлые панели. Изображения концепции взяты из его assets. Google Fonts требует сети; при недоступности используются системные шрифты.

Подробная сверка находится в [MOBILE_PARITY.md](MOBILE_PARITY.md).

Оба исходных интерфейса используют демонстрационные данные. Здесь нет подключения к реальным USV, входа через сервер, видеопотока, компьютерного зрения или лабораторного анализа. Карта — условная схема, координаты пересчитаны для иллюстрации. Демопроба копирует показатели из учебного набора. Пороги и оценки не подтверждают соответствие нормативам. SVG-снимок показывает синтетическую сцену, PDF формируется через печать браузера. На реальном устройстве нужны авторизация, транспорт телеметрии/команд и подтверждения выполнения; их контракт описан в сверке.

## Проверки

```powershell
npm run typecheck
npm test
npm run build
```

Тесты проверяют завершение маршрутов, RTL, отсутствие самоподключения, разряд батареи, порядок и границы дат отчёта, фильтры, защиту CSV и HTML-экранирование.

Стек сохранён: React 19, TypeScript, TanStack Start/Router, Vite, Tailwind, shadcn/ui, Recharts. Для воспроизводимой установки добавлен package-lock.json. Исходный bun.lock сохранён как часть истории проекта; для этой версии используйте npm ci.

Версия `@lovable.dev/vite-tanstack-config` зафиксирована на 1.7.0, как в исходном bun.lock: она сохраняет Cloudflare-сборку из wrangler.jsonc. Версия 1.8 меняет механизм деплоя на Nitro. После фиксации `npm audit` не сообщает уязвимостей.

Для просмотра production-сборки выполните `npm run build`, затем `npm run preview`. Предпросмотр запускается через локальный Cloudflare Workers runtime на http://127.0.0.1:3000 (публикация в Cloudflare не выполняется).

Для браузерного smoke-теста нужен Python с Playwright и Chromium. При запущенном предпросмотре выполните `python tests/browser-smoke.py`. Тест создаёт отдельный контекст браузера и сохраняет результаты в игнорируемую папку `qa-artifacts/`.
